Face à la recrudescence du vol d'identifiants : comment l'authentification multifacteur (MFA) est-elle devenue le pilier indispensable de la sécurité des accès en entreprise ?

01

Sujet, justification et objectifs

Sujet

L'authentification multifacteur (MFA) en entreprise : ses méthodes (SMS, application TOTP, notification push, clé FIDO2, passkeys), les attaques qui la contournent et son évolution vers une authentification sans mot de passe.

Pourquoi ce sujet

En option SISR, je serai chargé de mettre à disposition des services et d'en sécuriser l'accès (VPN, messagerie, serveurs). Mon stage en hardening Linux m'a montré que l'authentification est la première ligne de défense, et mon projet de bachelor en cybersécurité rend ce sujet central.

Objectifs

  • Repérer les technologies émergentes : FIDO2, passkeys, authentification sans mot de passe
  • Comprendre les nouvelles attaques : AiTM, MFA fatigue, vol de cookies, device code
  • Renforcer mes compétences : choisir et déployer la bonne méthode MFA selon le contexte

Journal de veille

Synthèses datées, du plus récent au plus ancien. Chaque fiche cite sa source et donne mon analyse personnelle.

28août 2026
Menace

Le « device code phishing » : contourner le MFA sans fausse page

L'attaquant démarre une demande de connexion « appareil » auprès de Microsoft et obtient un code court. Il pousse la victime à saisir ce code sur la vraie page Microsoft : elle valide son MFA normalement, et l'attaquant récupère les jetons d'accès. Aucune fausse page, aucun mot de passe volé. Changer le mot de passe ne suffit pas : il faut révoquer les jetons.

Mon analyse : c'est l'attaque qui m'a le plus surpris, car tous les réflexes classiques (« vérifier l'adresse du site ») ne servent à rien. Côté administrateur, la parade est de bloquer ce mode de connexion par accès conditionnel pour les comptes qui n'en ont pas besoin.

Source : Brandefense, 28/08/2026 →
21juil. 2026
Menace

Pourquoi la « MFA fatigue » fonctionne toujours

L'attaquant, qui a déjà le mot de passe, envoie des dizaines de demandes de validation push jusqu'à ce que l'utilisateur accepte pour que ça s'arrête. Des tests d'ingénierie sociale cités dans l'article montrent 15 à 25 % d'acceptation après plusieurs heures, surtout tôt le matin ou tard le soir.

Mon analyse : une notification push « Accepter / Refuser » est donc une faiblesse. En attendant les clés FIDO2, le number matching (taper le nombre affiché à l'écran) et la limitation du nombre de demandes sont des mesures simples à activer. Il faut aussi apprendre aux utilisateurs qu'une demande non sollicitée signifie que leur mot de passe est déjà compromis.

Source : SmarterMSP, 21/07/2026 →
14juil. 2026
Technologie

Microsoft fait des passkeys la méthode par défaut dans Entra ID

À partir du 1er septembre 2026, les utilisateurs qui utilisent le SMS ou l'appel vocal pour leur MFA sont invités à enregistrer une passkey. Le 1er février 2027, Microsoft arrête de fournir lui-même l'envoi des SMS et appels d'authentification : il faudra passer par un opérateur tiers payant.

Mon analyse : c'est un tournant concret : l'éditeur le plus répandu en entreprise abandonne le SMS, que l'ANSSI déconseillait déjà. Pour un technicien, cela veut dire accompagner les utilisateurs dans l'enregistrement de leur passkey et anticiper les cas particuliers (comptes partagés, personnes sans smartphone).

Source : SecurityBrief, 14/07/2026 →
07mai 2026
Technologie

Rapport FIDO Alliance : les passkeys deviennent la norme

Pour la Journée mondiale des passkeys, la FIDO Alliance estime à environ 5 milliards le nombre de passkeys utilisées. 68 % des entreprises interrogées en déploient ou en ont déployé pour leurs employés, mais 57 % utilisent encore des méthodes vulnérables au phishing pour la connexion quotidienne.

Mon analyse : les chiffres viennent d'un organisme qui promeut les passkeys, je les prends donc avec recul. Mais l'écart entre « on déploie » et « on utilise encore des codes » montre qu'il y a beaucoup de travail de migration en entreprise, donc des besoins en techniciens qui maîtrisent ces outils.

Source : FIDO Alliance, 07/05/2026 →
13avr. 2026
Menace

Vol de cookies de session : le MFA ne protège que la connexion

Après la connexion, c'est le cookie de session qui sert d'identifiant. Des logiciels espions (« infostealers ») les volent dans le navigateur et les revendent : l'acheteur entre dans le compte sans mot de passe ni MFA, tant que la session reste valide.

Mon analyse : le MFA n'est pas suffisant seul. Il faut le compléter par des sessions plus courtes, la réauthentification quand le contexte change (pays, appareil) et la sécurité des postes de travail, car c'est là que le cookie est volé.

Source : The Hacker News, 13/04/2026 →
04mars 2026
Menace

Tycoon2FA : un kit de phishing AiTM démantelé

Microsoft décrit Tycoon2FA, un service de phishing « clé en main » vendu dès 120 $ : une fausse page relaie identifiants et code MFA vers le vrai service et capture le cookie de session. Des dizaines de millions d'e-mails par mois, plus de 500 000 organisations visées. Microsoft et Europol ont perturbé son infrastructure.

Mon analyse : l'article confirme que les codes SMS, TOTP et les notifications push peuvent tous être contournés. Seules les méthodes résistantes au phishing (FIDO2, passkeys, Windows Hello) bloquent ce type d'attaque, car la clé vérifie elle-même le nom de domaine du site.

Source : Microsoft Security Blog, 04/03/2026 →
08janv. 2026
Obligation

MFA obligatoire pour le centre d'administration Microsoft 365

Depuis le 9 février 2026, impossible de se connecter au centre d'administration Microsoft 365 sans MFA, sans exception. Cette mesure suit l'obligation pour les comptes administrateurs d'octobre 2024 et l'extension aux outils en ligne de commande.

Mon analyse : les comptes administrateurs sont la cible la plus précieuse : en tant que futur technicien, je devrai moi-même utiliser un MFA robuste. Ce n'est plus une bonne pratique, c'est une condition d'accès.

Source : IT-Connect, 08/01/2026 →
05sept. 2025
Obligation

Azure : MFA obligatoire aussi en ligne de commande (phase 2)

À partir du 1er octobre 2025, Microsoft impose le MFA pour gérer les ressources Azure via Azure CLI, PowerShell, les API et les outils d'Infrastructure as Code. Selon Microsoft, le MFA bloque plus de 99,2 % des compromissions de comptes.

Mon analyse : c'est l'article qui a lancé ma veille. Je pensais que le MFA servait surtout aux utilisateurs ; il s'applique en fait aussi aux administrateurs et à leurs scripts. Les comptes de service (identités managées) ne sont pas concernés, ce qui montre qu'il faut bien distinguer humains et machines.

Source : Microsoft Azure Blog, 05/09/2025 →

Constat clé

Les attaquants ne devinent plus les codes : ils interceptent la session (AiTM), volent les cookies, épuisent l'utilisateur de notifications ou le font valider sur la vraie page (device code). Un MFA « classique » ne suffit plus.

Tendance de fond

Le standard FIDO2/WebAuthn résiste au phishing grâce à une signature cryptographique liée au domaine du site. Les passkeys le rendent accessible à tous et deviennent la méthode par défaut chez Microsoft depuis septembre 2026.

Recommandations

  • Généraliser le MFA sur messagerie, VPN et accès administrateurs
  • Abandonner le SMS au profit des passkeys ou d'une application
  • Activer le number matching contre la MFA fatigue
  • Clés FIDO2 pour les comptes critiques (admins, direction, RH)
  • Bloquer le flux « device code » s'il n'est pas utilisé
  • Former les équipes à refuser toute demande non sollicitée
